# アプリケーション仕様書 (Application Logic & Rules)

## アプリ名：『ローマ字マトリクス・ビルダー』 (Ver 1.0)

## 1. 概要とターゲット
視空間認知（VSI）と流動性推理（FRI）が優位で、処理速度（PSI）とワーキングメモリー（WMI）が平均的な児童向けのタイピング習得アプリケーション。
タイピングを「反射神経のゲーム」ではなく、「空間座標の把握」と「子音×母音のマトリクスを埋めるパズル」として再定義する。

## 2. 基本ルール (Core Mechanics)
### 2.1 評価の主軸（PSI保護）
* タイムリミット、カウントダウン、文字の落下など、時間を急かす要素は一切排除する。
* 「入力速度（WPM）」は計測・表示せず、「正答率（Accuracy）」とバックスペースを使わない「連続正解数（コンボ）」を評価基準とする。

### 2.2 エラーリカバリーとフィードバック
* **正解時:** チャイム音と共にマトリクスが獲得（色付け）される。
* **不正解時:** ブザー音は鳴らさず、小さく「カツッ」という鈍い音のみ。押したキーが一瞬グレーに沈む。画面の揺れや赤色フラッシュなどの過剰な視覚的罰は禁止。
* **ルートの再提示:** エラー直後、本来押すべき正解キー・ルートが明滅し、視空間（VSI）に直接働きかける。

### 2.3 ローマ字入力規則
* マトリクス化（子音×母音）の視覚的提示は原則として「ヘボン式（shi, chi, tsu, fu 等）」をベースとするが、実際のキー入力としてはヘボン式・訓令式（si, ti, tu, hu 等）の両方を正解として許容する。

### 2.4 セッションの区切りとリザルトフロー
* 1回のプレイ（セッション）は「10問で1セット」とする。
* 10問完了後、自動的にリザルト画面（児童向けダッシュボード）へ遷移し、「よくできました！」と達成感を提供するフィードバックを行う。

## 3. レベル進行とスキャフォールディング（足場かけ）
発達の最近接領域（ZPD）に基づき、支援を段階的にフェードアウトする。
* **Stage 1: ベースキャンプ（母音とアンカー）**
  * 母音（A,I,U,E,O）のみ出題。F・Jキーを基準とした絶対座標をマッピング。
* **Stage 2: マトリクス発見（か行・さ行など）**
  * 子音＋母音の法則性（FRI）を理解。ナビゲーション線（光る道筋）による視覚支援をフル稼働。
  * 指導者ダッシュボードで設定された「閾値（例: 90%正答で次へ）」をクリアするごとに、対象となる行が自動的に追加されていく。
* **Stage 3: 陣取りゲーム（支援の段階的縮小）**
  * 短いランダム単語を出題。「オート・リジェクト（誤入力の自動弾き）」は維持しつつ、正答率に応じてナビゲーション線を徐々に消去する。
* **Stage 4: 独立への航海（一般タイピングへの移行）**
  * 仮想キーボードを非表示化。「オート・リジェクト」を解除し、誤入力時はバックスペースによる自己修正を要求する（一般的なテキストエディタ環境への適応）。

## 4. 指導者向けマニュアル（個別指導ガイド）
* **【警告】** 聴覚的な長文説明や多重課題は、WMIのボトルネックを引き起こす。
* **【対策】** 「1アクション・1センテンス」を徹底。「画面を見せながら、指差しと実作業を伴って」一つずつ法則を発見させるよう誘導すること。
